# MGSF Living Local Agent Orchestra M0.2

**Experimental / stacked onto M0.1.** No current Cockpit UI, MCP protocol, or Shared Brain service is changed.

## Purpose
Promote the M0.1 read-only LiteRT Godot diagnostic adapter to an explicit, predictable division of labor:

1. **Task router:** low/medium risk GDScript reviews may go to LiteRT when a local model file is present.
2. **Manual handoff:** architecture, creative decisions, high-risk tasks, or missing local models go to a **copy-only Codex handoff**, never an automated cloud model call.
3. **Evidence:** print a JSON review result with sampled source fingerprint, time, limitations, and untrusted findings; do not change project files.
4. **Quality gate:** compare finding IDs only against a human-verified bug list, not unchecked model assertions.
5. **Shared Brain candidate:** emit a *pending* candidate containing only a human-curated note and a provenance hash. No live Shared Brain write.

This design honors the Cockpit's strict read-only MCP boundary. The Python experiment is separate, opt-in, and is not added as an MCP tool.

## Quick start
Install the model/SDK using the M0.1 README first. These plan, score and handoff commands do not need any SDK, GPU, or API key:

```bash
cd experiments/local-agent-bridge

# Offline tests
python -m unittest discover -s . -p 'test_*.py' -v

# Examine a task; no model call
python orchestra.py plan --project /path/to/godot-project --category gd_review --risk low

# Explicit local-only inference: stdout result can be captured manually
python orchestra.py run-local --project /path/to/godot-project \
  --model-path ~/.litert-lm/models/gemma4-26b/model.litertlm > /tmp/godot-local-review.json

# Hand-reviewed copy-only Codex packet, no Codex API invoked
python orchestra.py handoff --result /tmp/godot-local-review.json

# Candidate for manual Shared Brain curation; NOT an upload
python orchestra.py candidate --result /tmp/godot-local-review.json \
  --curated-note "Manually check this signal lifecycle before proposing a fix"

# Purely synthetic scoring example, NOT a real evaluation
python orchestra.py evaluate --benchmark fixtures/toy_benchmark.json
```

**Redirecting stdout** writes a result wherever the operator chooses. It does not modify the Godot project. Avoid collecting source-derived diagnosis in a shared or publicly synced location.

## Decision rules

| Input | Outcome |
| --- | --- |
| gd_review + low/medium risk + model path exists | local_litert (only if run-local explicitly invoked) |
| gd_review + missing model | human_codex_handoff |
| architecture / creative_direction | human_codex_handoff |
| any high risk task | human_codex_handoff |
| all routes | human review before any external execution or knowledge promotion |

The presence of a model file does *not* prove that a compatible LiteRT runtime or GPU is available. Each run may fail. Cloud provider integration and automatic deployment are deliberately excluded.

## Verification
- Offline unit tests cover deterministic routing, high-risk denial, mock local execution, copy-only handoff, human approval gate and human-labeled score calculation.
- GitHub Actions runs both M0.1 and M0.2 tests without installing AI dependencies.
- **Not yet verified:** real LiteRT inference, GPU consumption, latency, accuracy against annotated Godot cases, actual Codex execution, Godot MCP integration, or Shared Brain ingestion.

## Threat model / limitations
- Source and model output are untrusted. A human must check claims and possible embedded instructions before sharing with Codex.
- Source fingerprint covers only the bounded sampled scripts (up to M0.1's file and character caps). It is not a repository commit hash.
- The local review text can contain sensitive snippets echoed by a model; do not distribute or upload results without review.
- A candidate is explicitly `approved: false` and contains no raw source or raw local diagnosis.
- No model is allowed to add MCP write, command, environment, secrets, browser, or authentication capabilities.
- API model costs are zero for local inference in the result, but hardware/power costs are **excluded**.
